Two new capabilities — Discord chat and a Linux supervisor installer — plus a
round of security and reliability hardening. No breaking config changes; a few
Windows-only behavior changes are noted below.

## Getting the binary

This is about *obtaining the `shipmates` executable*. (It's unrelated to the
`shipmates ship install` subcommand below, which registers the supervisor as a
service once you already have the binary.)

Two ways work:

- **Download a release build** from the assets below —
  `shipmates_0.6.0_<os>_<arch>.tar.gz` (macOS/Linux) or `.zip` (Windows). The
  persona catalog is embedded, so the single executable is all you need:

  ```sh
  tar -xzf shipmates_0.6.0_linux_amd64.tar.gz shipmates
  sudo mv shipmates /usr/local/bin/
  shipmates --version
  ```

- **Build from source**: `git clone` the repo and `go build -o shipmates .`.

`go install github.com/luthermonson/shipmates@v0.6.0` does **not** work this
release, and this is the *only* acquisition method affected: shipmates pins a
fork of `rancher/remotedialer` (an unmerged data-race fix) via a `replace`
directive, and Go refuses to `go install` a module carrying `replace` directives.
Use either method above until
[rancher/remotedialer#265](https://github.com/rancher/remotedialer/pull/265)
merges upstream and the replace can be dropped.

## Features

### Linux `ship install` (systemd)
`shipmates ship install` now works on Linux, completing the trio alongside the
Windows Scheduled Task and macOS launchd agent. It writes a systemd **user** unit
(`~/.config/systemd/user/shipmates-ship.service`), reloads, and enables it. Two
Linux-specific details are handled for you: the install-time `PATH` is baked into
the unit (a `--user` unit does not inherit your login shell env, so otherwise
`ship serve` couldn't find `claude`/`git`), and `loginctl enable-linger` is
enabled best-effort so the ship survives logout — if linger can't be set it warns
and continues rather than failing the install. `shipmates ship uninstall` removes
the unit; it leaves linger alone.

### Discord chat (experimental)
`shipmates discord` connects your crew to Discord: an allowlisted message in a
mate's channel is delivered to that mate as a tell, and the mate's replies post
back as its own bot. Multi-bot is supported — each mate can speak as a distinct
Discord bot in its own channel, configured in `~/.shipmates/discord.yaml`, with an
optional all-hands channel that mirrors every mate's output. Bot tokens are named
by env vars, never stored in the config file (the same operator-owned-secret rule
as the OpenAI runtime and personas). A single-bot mode via env vars works with no
config file.

Security throughout: the inbound allowlist is fail-closed, Discord text is treated
as data (never interpreted as a command), outbound `@everyone`/`@here`/mention
strings are stripped (plus `AllowedMentions: none`), mate output is run through the
terminal-escape scrubber, and the transport authenticates to the captain API with
its per-run bearer token.

**Marked experimental:** the code is complete and unit-tested, but the live
Discord wire (gateway connect, message delivery, posting) requires a real bot in a
server to exercise — see `docs/discord.md` for the setup and smoke-test steps.

## Security & hardening

- **Permission-gate residual bypasses closed.** Shell here-strings
  (`bash <<< '…'`) and PowerShell `-Command` / `-EncodedCommand` (base64/UTF-16LE,
  now decoded) are evaluated as their own command lines instead of laundering an
  inner command past a deny rule. Windows-specific gaps found in review are also
  fixed: a backslash-spelled interpreter path
  (`C:\…\powershell.exe`) is now canonicalized so extraction still applies, and
  unquoted multi-token / colon-value `-Command` forms are handled. Malformed
  `-EncodedCommand` fails closed.
- **Brig article Windows parity.** Articles that previously guarded only Unix paths
  (`/etc/**`) now also cover the Windows equivalents (`C:\Windows\**`, the Startup
  folder), and path matching for volume-rooted Windows paths is now
  case-insensitive — so `c:\windows\…` can no longer walk past a `C:/Windows/**`
  deny.
- **Bead-id validation unified.** A third, divergent bead-id validator that lacked
  the `..` traversal check now delegates to the shared `internal/beadid` rule,
  closing the gap without rejecting any real bd id.
- `govulncheck` reports **0 affected vulnerabilities**.

## Reliability & tooling

- **Memory-watchdog test runner** (`scripts/safe-test.{ps1,sh}`, documented in
  `CONTRIBUTING.md`). It runs the suite and kills any `*.test` child that crosses a
  memory cap, so a runaway test can't take the machine down — with a Linux fix
  (match on `argv[0]`, not the 15-char-truncated `comm`) so packages like
  `permissions` aren't silently uncovered. Contributors should run tests through it;
  it also documents the rule that a bound must never be verified by disabling it and
  running unbounded.

## Windows behavior changes (not breaking, but notable)
- Path deny rules on volume-rooted Windows paths now match case-insensitively.
- Backslash-spelled interpreter invocations are now subject to the same command
  extraction as forward-slash ones.

These only tighten enforcement; legitimate commands are unaffected.
