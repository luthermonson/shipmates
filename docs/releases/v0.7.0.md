## `shipmates doctor`

A read-only diagnostic that checks the external tools and config surfaces
shipmates depends on and reports **OK / WARN / FAIL** with a fix hint for each —
the checks you'd otherwise run by hand when a setup misbehaves. It exits
non-zero only if something genuinely can't work, so it's usable in a pre-flight
or CI hook.

What it checks, grouped:

- **Toolchain** — `claude` on PATH (a FAIL if missing — it's the hard
  dependency), `git`, and `bd` (only expected when Beads is configured).
- **Config** — your `~/.shipmates/` files parse cleanly (`config.yaml`,
  `ship.yaml`, `personas.yaml`, `discord.yaml`); the selected runtime is usable
  (for `openai`: `base_url` set, `api_key_env` populated, no plaintext endpoint);
  configured secret env vars are present.
- **Ship** — captain session files have safe (0600) permissions, whether a
  captain is currently running, and whether the ship supervisor is installed for
  your OS.
- **Fleet** (only if configured) — the fleet URL is `https`/loopback, the token
  is set, and the policy cache is present.
- **Personas** — installed personas resolve, and it flags any whose checkout
  tries to set operator-only keys.

**FAIL** (the only status that exits non-zero) is reserved for genuinely broken
or insecure states: `claude` missing, a malformed config file, a selected
runtime that can't initialize, or a plaintext fleet URL to a non-loopback host.
Everything optional or degraded is a WARN; an absent config is just info.

It is strictly read-only — it never creates, changes, or deletes anything, never
starts a process beyond a health probe, and **never prints a secret** (env vars
are reported set/unset by name only).

`govulncheck` reports 0 affected vulnerabilities.
