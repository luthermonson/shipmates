A cross-platform hardening patch. No new features, no config changes — three
correctness/safety fixes found by a sweep for the bug class v0.6.0's CI exposed:
code verified on the Windows dev box that behaves differently on the Linux/macOS
fleet. Get the binary the same way as before (see the v0.6.0 notes; `go install`
is still blocked by the remotedialer `replace`).

## Fixes

- **Containment now bounds the whole process tree on Linux/macOS, not just the
  root process.** The resource watchdog measured RSS/CPU for only the top-level
  process, while it *killed* the whole process group and the Windows Job Object
  already enforced memory tree-wide. So a tool subprocess that hogged memory or
  spun could slip past the cap on Linux/macOS — masked on Windows, where the
  kernel enforces it. The Unix samplers now sum usage across the child's process
  group, matching the scope that's killed. (This is a security control that was
  silently under-enforcing.)

- **The server's live-crew spawn no longer drops the final result frame or leaks
  processes.** `spawnCrewLive` used `cmd.StdoutPipe`/`StderrPipe` with a
  concurrent `cmd.Wait()` — the same teardown race fixed in the runtime adapters
  in v0.5.0, but missed in the server's own path. On the resume path it could
  drop a mate's final `result` event (cost/model) and truncate stderr; and the
  child was reaped only on one path, leaking a zombie/handle on every fresh
  spawn over a long-running ship. The server now owns the pipes and reaps every
  child with drain-then-close ordering.

- **Brig path denies can no longer be case-evaded on UNC network shares.** The
  matcher's case-insensitive fold fired only for drive-letter paths (`C:\`), so a
  UNC path (`\\server\share\...`) on a Windows ship with a network-share checkout
  was matched case-sensitively — a deny like `Write(**/.claude/settings.json)`
  wouldn't fire against `...\.CLAUDE\settings.json`. UNC paths are now normalized
  and case-folded like drive-letter paths on any host.

`govulncheck` reports 0 affected vulnerabilities.

## Not in this release
A few lower-severity stragglers of the same classes are tracked for later:
cross-OS `update` manifest keys, two unconditional case-folds
(`berth.CurrentIsBerth`, `ship.AddProject`), and a possible macOS `ps args`
truncation in the test-watchdog script. Discord chat remains **experimental**
(its live gateway wire is still unverified against a real bot).
